PROORGANIC PUBLIC RESEARCH COLLECTOR — WINDOWS

Что запускать
=============
Дважды кликните RUN_PROORGANIC.bat.

Он сам:
1. найдёт Python;
2. создаст .venv;
3. установит зависимости;
4. запустит полный сбор;
5. положит результаты в output\latest;
6. откроет HTML-отчёт и Excel.

ВАЖНО
=====
В этой версии НЕТ зависимости от lxml.
BeautifulSoup использует встроенный html.parser, поэтому ошибка
"Couldn't find a tree builder ... lxml" больше не должна возникать.

Что собирается
==============
С публичного сайта PROORGANIC:
- страницы и типы страниц;
- карточки товаров;
- заголовки и основные продуктовые данные из публичного HTML/JSON-LD;
- все видимые ссылки и CTA;
- направления ссылок: собственный сайт, Telegram, Ozon, Wildberries, Taplink и др.;
- UTM/yclid/gclid/erid, если они видимы в URL;
- публичные технические сигналы, в том числе наличие Яндекс Метрики;
- лексическая карта продуктовых задач.

Из публичного Telegram:
- посты;
- дата;
- текст;
- просмотры;
- тип медиа;
- публичные ссылки;
- UTM;
- посты с "Тарифом доверия";
- публичные направления покупки;
- темы/потребности по тексту.

Что получается
==============
output\latest\report.html
    Читаемый сводный отчёт.

output\latest\PROORGANIC_public_research.xlsx
    Excel с отдельными листами.

output\latest\csv\
    Исходные таблицы CSV.

output\latest\PROORGANIC_public_research.sqlite
    SQLite-база.

output\latest\dashboard_data.json
    JSON для последующего подключения к прототипу сайта.

output\latest\routes.graphml
    Граф наблюдаемых публичных маршрутов.

output\runs\YYYY-MM-DD_HH-MM-SS\
    Архив каждого отдельного запуска.

Методологическая граница
========================
Сборщик восстанавливает ПУБЛИЧНО НАБЛЮДАЕМЫЕ маршруты:
что опубликовано, куда ведут ссылки, какие CTA и разметка видимы.

Он НЕ может снаружи доказать:
- фактические клики;
- конверсию;
- продажи после конкретного поста;
- LTV;
- повторные покупки;
- внутреннюю атрибуцию;
- CRM-когорты.

Именно поэтому эти результаты можно использовать как основание для вопросов
к Метрике, CRM и внутренним данным, а не выдавать за внутреннюю аналитику.

Быстрая проверка
================
После первого полного запуска окружения можно использовать RUN_FAST_TEST.bat.

Если окружение Python сломалось
===============================
Запустите RESET_ENV.bat, затем снова RUN_PROORGANIC.bat.

Если сбор упал
==============
Пришлите:
- весь текст консоли;
- output\runs\последний_запуск\run.log;
- FATAL_ERROR.txt, если он появился.
